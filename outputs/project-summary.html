Phase 3 Design — Architecture & T-Shirt Estimates

Design translates epics into a concrete Salesforce architecture — choosing the tech pattern for each capability — and assigns a complexity size using an 8-dimension rubric.

Architecture Foundations

Platform
Salesforce Core + Agentforce
No Industry Cloud, Data Cloud, or Marketing Cloud. Core platform only — clean and focused.
Org Strategy
Single persistent DE org
No scratch org, no DevHub. Deploy once, reset between demos via anonymous Apex.
Automation pattern
Apex @InvocableMethod per Action
Flow can't do datetime overlap arithmetic. Each of the 5 agent actions calls its own dedicated Apex class.
Security
OWD + 2 Permission Sets
Match_Organiser (agent + records) and Match_Admin (master data CRUD). Standard, no Apex-managed sharing.

The 3 Apex Classes Behind E03 (hardest epic)

StaffAvailabilityCheckerbacks Action 3 — Check Staff Availability
Datetime overlap SOQL: finds staff with conflicting assignments using the touching-times rule (start B < end A = conflict). Also checks stadium conflict (same stadium, overlapping window). Returns available staff by role, or a stadium-blocked error.
StaffAssignerbacks Action 4 — Assign Staff
Re-validates availability inline before writing (defensive — catches race conditions). Inserts Match_Assignment__c. Updates Match status from Draft → Staffing on first assignment. Returns success message or conflict error.
MatchConfirmerbacks Action 5 — Confirm Match
Checks crew minimums: Ground Staff ≥ 4, Commentators ≥ 2, Camera Operators ≥ 3. If all pass: updates Match status → Set, returns crew summary. If any fail: returns "Need X more [Role] before confirming."

Architecture Decisions Made in Design

DecisionRationale
Flow or Apex for scheduling?
Apex @InvocableMethod — Flow can't do datetime overlap arithmetic across records. One class per action.
Match_Assignment → Match: M-D or Lookup?
Master-Detail — cascade-delete. Assignments are owned by and deleted with their Match.
Where do crew thresholds live?
Hardcoded Apex constants for Phase 1. Custom Metadata is the Phase 2 upgrade path.
One Apex class or one per action?
Compound-per-action (one class per action) — single responsibility, easier to test.
